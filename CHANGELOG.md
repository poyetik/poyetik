# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- The render hash is specified (`spec/render-hash.md`: byte layout, byte order, versioning rule, a worked example), with known-answer vectors (`spec/render-hash-vectors.json`: `-0`, a subnormal and a NaN payload among them) that the Rust, TypeScript and oracle implementations are all tested against.
- `roadmap title <text>` sets the board title, the heading of the public roadmap page, which no command could change; the roadmap is now titled "Poyetik".
- `cargo xtask check` checks the history: every commit message follows the convention, and every `feat`, `fix`, `perf` or breaking commit since the rule was introduced updates the changelog. It also requires CI to pin every action to a full commit hash, the Cargo tools to exact versions (which the preflight now requires locally too) and Node.js to `.node-version`.
- The pre-push hook (`cargo xtask pre-push`) refuses a working tree with uncommitted changes and a pushed commit other than the one checked out, so that the check validates exactly what is pushed.
- `GLOSSARY.md`: the words of the project, with the name each takes in the patch format and the code. READMEs for the roadmap, the oracle and the shared policy; `cargo xtask check` now requires a README in every TypeScript package, every part named in the README of its folder and every folder in the root README.
- The shared TypeScript policy (`@poyetik/config`) is itself checked: each lint rule and strict compiler setting is proven, by a fixture that breaks it, to reject exactly what it forbids, with 100% coverage and no surviving mutant; the ESLint configuration is now TypeScript, linted by itself, and a step of `cargo xtask check`.
- `cargo xtask check` starts by checking the platform (macOS or Linux; Windows through WSL2) and every tool it needs, Node.js 22.18 or later included, naming what is missing and how to install it; `cargo xtask list` lists the checks. `.gitattributes` keeps LF line endings everywhere (the git hooks are shell scripts), and `pnpm install` no longer fails outside a git work tree.
- A membership gate in `cargo xtask check`: the `package.json` files tracked by git must be exactly those the version check reads, every TypeScript package must have its checks and reports run, and every crate must take the workspace version. A package added without being wired into the checks now fails it.
- `cargo xtask check` reads the coverage summary and the mutation report of every TypeScript package itself (100% of lines, statements, functions and branches; no surviving or uncovered mutant), from report directories emptied at each run: lowering a package's own threshold, or a package no longer writing its reports, now fails the check.
- `captureEngine` (engine-wasm web API): captures live the first frames the engine renders, from where its processor really started, as `renderOffline` does offline (`OFFLINE_MARGIN` is renamed `START_MARGIN`, shared by both).
- `mutants-equivalent.txt` and a gate in `cargo xtask check`: every TypeScript mutant disabled as equivalent is listed there with its justification; a disable comment that is not listed, a stale entry, or a broader disable (a whole file, every mutator) fails the check.
- The WebAssembly module exports `engine_abi_version`: the interface identity ("PY") and version (1), checked before anything else by the JavaScript side.
- No-allocation proofs beyond single boxes: the plan laws check that rendering any random built plan allocates nothing, and the WASM engine tests check `Engine::process`, `Instance::process` and `engine_process` (at every sample rate of the matrix). The CLAUDE.md claim about an `assert_no_alloc` check, which did not exist, is corrected.
- Seven conformance cases from the test matrix: 8 kHz near and above Nyquist and above the sample rate, 44.1 kHz with a partial last block, 20 kHz at 48 kHz, 19,999 Hz at 384 kHz, and 0 Hz. The Node tests and the four browsers render the whole corpus (each at its own rate) and check it is complete; live captures cover 48 and 44.1 kHz.
- `Plan::render_into` renders the next frames into a caller buffer, without allocating; it continues exactly like `Plan::render`.
- `engine-core`: the box contract (`Object`, `ObjectSpec`), strong types (`SampleRate`, fixed 64-frame `Block`, `NodeId`) and the deterministic execution plan (validation, topological sort, cycle detection, allocation-free processing).
- `engine-objects`: the first boxes, `osc~` (sine oscillator, 440 Hz by default) and `dac~` (stereo audio output), and their registry.
- `engine-testkit`: the laws every registered box must respect (metadata, determinism, finite output, no allocation while processing), checked with random inputs from a fixed seed.
- Patch format, version 1 (`spec/patch-format.md`), read by `engine-patch`.
- `engine-core`: `Plan::render` renders frames offline.
- `engine-hash`: canonical SHA-256 hash of a render, cross-checked with an independent implementation.
- `engine-cli`: renders conformance cases to WAV files, checks and blesses reference hashes.
- First conformance case, `sine-440`, checked by `cargo xtask check`; `cargo xtask bless` is the only way to update reference hashes.
- `engine-wasm` (`bindings/wasm`): the engine as a WebAssembly module with a minimal C interface, and its TypeScript glue (`AudioWorklet` processors, main-thread API, offline rendering, live capture), proven bit-identical to the native engine in Node and in Chromium, Firefox, WebKit and mobile WebKit.
- Playground (`apps/playground`, Vite + React): a 440 Hz sine from the Rust engine with an on/off button, a live Canvas 2D oscilloscope and its measurements (frequency, peak, sample rate), tested on Chromium, Firefox, WebKit and mobile WebKit, with accessibility checks.
- `engine-wasm`: `tap` streams the output of a node to the main thread; `capture` is built on it.
- Independent conformance oracle (`tooling/oracle`, TypeScript): rereads the WAV file of every case, recomputes its hash with Node's own SHA-256 and checks each channel against its mathematical definition (`conformance/expectations.json`); `engine-cli export` writes those files; both run in `cargo xtask check`.
- `@poyetik/config` (`tooling/config`): the strict TypeScript and ESLint configuration shared by every TypeScript package.
- `xtask`: Miri runs the tests of the engine FFI; the `bindings/wasm` package checks (build, types, lint, 100% coverage, mutation testing, end-to-end tests) are part of `cargo xtask check`.
- `xtask`: `cargo xtask check`, the single quality gate run by the pre-push hook and CI.
- Monorepo layout: `spec/`, `crates/`, `bindings/`, `apps/`, `conformance/`, with one Cargo workspace and one pnpm workspace at the root.
- Public roadmap (`apps/roadmap/`): kanban stored in `board.json`, driven by a CLI, rendered as a static page with collapsible steps.
- Project rules in `CLAUDE.md`.

### Changed

- The roadmap page shows its columns in classic kanban order, Later, Next, In progress, Done, from left to right; on a phone, where the columns stack, In progress still comes first.
- **Breaking:** the project is named Poyetik. Every package is `@poyetik/…`, and the WebAssembly module's interface identity is now "PY" (`0x5059_0001`): a module built before the rename is refused by the new JavaScript side, and the reverse.
- **Breaking (roadmap CLI):** the steps of a card are steps everywhere, as on the page: the command `task add|done|undo|edit|rm` is now `step add|done|undo|edit|rm`, and the messages say "step". The data file keeps its `tasks` key, unchanged byte for byte.
- The step names of `cargo xtask check` all start with a capital letter (checked), and the engine documents that its output is never clipped or sanitized: the final output stage belongs to the host until the engine defines its own output policy.
- Names say what they hold, in Rust and TypeScript alike: no single-letter names but `i`, `j`, `x` and `y` (Clippy `min_ident_chars`, ESLint `id-length`; a Rust trait implementation's parameters may keep the trait's names, such as `f` in `Display::fmt`, which Clippy does not flag), and in TypeScript no declaration hiding another (`no-shadow`, even before the outer declaration); 256 names were renamed.
- Every named TypeScript item is documented, exported or not (functions, classes and their members, types, module-level constants), as the Rust items already were: the JSDoc rule no longer checks exported declarations only.
- The engine test bench is compiled into `dist/e2e-site/`, not next to its source behind a nested `.gitignore`; the membership gate now refuses any `.gitignore` but the root one.
- The tools shared by several TypeScript packages (TypeScript, Vitest, Playwright, Stryker, ESLint, axe, Node types) have one version each, in the pnpm catalog of the workspace; the Node type definitions follow the Node version the packages require (22.18), not Node 26, and the roadmap no longer allows a newer TypeScript than the others.
- The counting allocator of the tests is its own crate, `engine-alloc-counter`, checked by Miri; `engine-testkit` and the engine and instance modules of `engine-wasm` forbid unsafe code, and `cargo xtask check` fails when any file but the two audited ones lifts the lint against unsafe code.
- Roadmap: only a card in the In progress (`doing`) column has a step in progress; a card waiting in another column shows nothing in progress, and `step done <id>` without a step number fails for it.
- **Breaking:** the oracle and the roadmap CLI follow the same command-line contract as `engine-cli` and `cargo xtask`: exit code 2 for a usage error (the roadmap used 1), one `error:` line naming the file (the oracle's JSON errors did not, the roadmap printed stack traces for unreadable files), and a closed stdout ignored instead of crashing. The contract is written in CLAUDE.md.
- `cargo xtask` exits with 2 on a usage error, names the command and its exit code (or the signal) when a step fails instead of "command failed", and ignores a closed stdout.
- **Breaking:** `engine-cli` exits with 2 on a usage error (usage on stderr) and with 1 when a command fails, with one `error:` line; `run` returns a `CliError` telling the two apart. A closed stdout (`| head`) no longer turns a success into a failure.
- The playground shows every state the player reaches: starting, playing, paused by the browser (with Resume), stopping, failed (with the reason next to the button and linked to it), instead of showing "Playing" while silent. Starting twice or stopping during a start is safe. The sound fades in and out over 20 ms and the device is released only after the fade, on the audio clock: no click. A browser lacking a secure page, Web Audio, AudioWorklet or WebAssembly is told what is missing. The button keeps the keyboard focus across transitions (`aria-disabled` instead of `disabled`) and looks different while it stops the sound.
- **Breaking:** `LoadedPatch` (engine-wasm web API) is a class only `loadPatch` creates, with its own copies of the bytes: a patch the engine did not check cannot be passed to an engine node. `createEngineNode` takes an `onFailure` callback and returns `{ node, ready }`: the processor tells the main thread whether it loaded the patch, and reports a later failure (a trap) once, instead of falling silent unnoticed. `renderOffline` rejects instead of returning silence when the processor fails.
- **Breaking:** conformance expectations no longer declare a tolerance (`max_error`, refused if present). The oracle derives the largest allowed distance from the ideal sine, term by term (binary32 output rounding, binary64 phase accumulation over the case length, evaluation), and computes its reference with an exact phase reduction, so it stays exact however long the case (up to 2^29 frames). The bound went from a guessed 1e-6 to 2.98e-8 at 1 s; a phase computed in binary32 (1.7e-3) or a gain off by 5e-7 is rejected. The `osc~` tests use the same bound.
- **Breaking:** the patch of each conformance case is its own file, `conformance/patches/<name>.json`, and every runner (native CLI, Node tests, browser bench) passes its bytes to the engine unchanged. The runners used to rewrite the patch from a parsed copy, which could hide differences (a repeated parameter was silently merged; JavaScript writes `-0` as `0`). `engine-cli render` takes the case and the patch files. A case without its patch, or a patch without its case, is an error.
- The playground plays the same document as the sine-440 patch of the conformance corpus (compared after parsing by a test), whose render has a reference hash.
- **Breaking:** `Patch` is a validated type, built only by `Patch::new`: node ids are unique, cables are never repeated, and a patch holds at most 65,536 nodes and 262,144 cables. The cables into an inlet are summed in a fixed order (source id, then outlet), whatever the order of the document. The patch reader also refuses documents over 16 MiB and a parameter named twice in one node.
- **Breaking:** `Plan::render` continues exactly where the previous call stopped (rendering `a` then `b` frames equals rendering `a + b`), and returns `CoreError::RenderTooLong` instead of failing when the samples cannot be held in memory.
- Execution order is computed with Kahn's algorithm, in O((N + E) log N) instead of O(N²·E): a patch of 16,000 boxes is ordered in milliseconds instead of seconds. The order is unchanged.
- Error messages name the faulty element once and say what is expected ("node 2 is declared twice", "invalid sample rate: 5 Hz (supported: 8000 to 384000 Hz)").
- The conformance CLI refuses a case whose patch has no audio output, instead of rendering nothing.
- The box laws (`engine-testkit`) run at every sample rate of a shared test matrix (8 kHz to 384 kHz, including 44.1 kHz), with special inputs (signed zeros, subnormals), a long run and parameters away from their default; a box that fails at any of them fails the laws. The matrix is also published as `conformance/test-matrix.json` for the TypeScript tests.

### Fixed

- The oracle follows the stream part of the command-line contract, like the Rust tools: a broken stderr no longer changes its exit code, and a stdout error other than a closed reader is one `error: cannot write to stdout: <code>` line and exit code 1 (never hiding a usage error's 2) instead of a stack trace.
- The oracle reports a usage error as one line, `error: <reason> (see: oracle help)`, as the command-line contract requires, instead of printing its usage on stderr with no `error:` prefix and no reason; `oracle help` prints the usage on stdout.
- The oracle's error bound is derived regime by regime of cycles per sample (below 1, and from 1 to 4, where the phase additions are exact), and an expectation's frequency must lie in [0, 4 × sample rate), the domain where the bound holds; the previous derivation was wrong from one cycle per sample on, and the 2 to 4 cycles regime (19,984 Hz at 8 kHz) is now tested.
- The oracle's error bound no longer fails a correct render of a very quiet sine (amplitude below 2^-125, whose samples are subnormal), and an expectation's start phase must lie in [0, 2π), the range the bound is derived for.
- The oracle reads the duration of a case file in the same domain as its expectations, 1 to 2^29 frames: a longer case, whose reference would not be exact, is rejected instead of being judged.
- The oracle rejects an expected frequency that is not exactly a binary32 value. It rounded the number `JSON.parse` had already rounded to binary64, a double rounding one ulp away from the engine's correct rounding for a text near a binary32 midpoint, and its bound would then have failed a correct render.
- The roadmap page draws its own keyboard focus ring on a card's steps toggle, the same in every browser, instead of each browser's default; tests reach it with Tab, open and close the steps with Enter and Space, and check the ring's style, width and contrast.
- Roadmap page: each column heading reads its count with a unit for screen readers ("In progress 2 cards"), the card lists keep their list role in WebKit, which drops it from lists without bullets, and a word longer than a card is wide wraps instead of pushing the card out of its column.
- The roadmap CLI refuses an option a command does not take (`rm 3 --title x`) and an argument given to a command that takes none (`list doing`, which listed every card), as usage errors; its help says how to give a value starting with `-`.
- The roadmap CLI keeps its exit code when stderr is closed (a usage error stays 2), and reports any stdout failure other than a closed reader as one `error: cannot write to stdout: <code>` line with exit code 1, instead of a stack trace.
- Roadmap CLI errors name the board file when it is invalid (`error: invalid board.json: …`), give a read or write failure as its system code (`error: cannot read <file>: ENOENT`) instead of repeating the path, and refuse a board that is not valid UTF-8, whose bytes were silently replaced and then written back by the next command.
- Roadmap validation errors locate a card by its id and its 1-based entry in the file (`card #4 (entry 3)`), or by its entry alone while its id is not proven; they used to say `card #3` for the 0-based position, which named another ticket.
- The roadmap no longer creates duplicate card ids past 2^53: ids and `nextId` must be safe integers, `add` refuses to create a card when no safe id is left, and an id typed beyond the safe range is invalid instead of naming another card.
- The roadmap refuses a truncated date in `board.json` ("2026", "2026-11"), which it used to accept as a YYYY-MM-DD day: a date must write itself back exactly.
- Pushing or committing from a linked git worktree no longer corrupts the main repository: git hands the hooks variables naming the repository (`GIT_DIR`, `GIT_INDEX_FILE` …), which reached the tests run by the check, and a test running git in a temporary directory then set `core.bare` and staged files in the real repository. The hooks unset them, and every command `cargo xtask` runs is started without them; tests push and commit from a real linked worktree.
- The roadmap dev server (`pnpm dev`) shows the page styled again: the strict Content Security Policy blocked the styles the dev server injects inline. The page now declares no policy in development mode only; the build and the tests keep the strict one.
- The TypeScript coverage gate refused a package whose code has no branch (0 of 0): branches may now number zero, while lines, statements and functions must still be measured.
- An empty conformance corpus fails `engine-cli check`, `bless` and `export`, and the oracle, instead of passing; the roadmap refuses dates that are well formed but not days of the calendar (2026-02-31, 2026-13-01).
- The roadmap's Astro templates are under coverage (`Board.astro`, and `index.astro` now rendered by a test), and the component test catches a card that would render an empty description or milestone (it checked an empty board, which has no card). Mutation testing of templates is roadmap #15.
- The WebAssembly engine module is reproducible: built with the paths of the Cargo home and of the repository remapped (it embedded `/Users/...` paths), from the artifact path cargo reports (`CARGO_TARGET_DIR` works), and `pnpm test:reproducible` checks that two builds in fresh target directories are identical and contain no path of the machine.
- The oracle reads WAV files of any number of chunks: the chunk reader was recursive and a file of about 10,000 empty chunks (80 KB) overflowed the stack (a RangeError instead of a WAV error).
- Playground: the oscilloscope has one backing pixel per device pixel, sharp on high-density screens (it was blurry and thin on phones), keeps its colors in forced colors (high contrast: the trace was at 1.91:1 on a forced white background), and is described by its measurements for assistive technologies. Both web apps have a favicon (a 404 before). The end-to-end tests fail on any console error or failed request, not only on uncaught errors.
- Roadmap: the In progress column comes first, then Next, Later and Done: on a phone the work under way no longer comes after the backlog.
- Playground oscilloscope: the history is 85 ms at every sample rate (it was 4096 samples, 10.7 ms at 384 kHz, too short to trigger below 1500 Hz there), and the trace is shifted by the fraction of a sample where the signal crosses zero, so it stands still instead of jittering by up to a sample. The frequency is shown only where it is accurate (at least three periods, at most a twentieth of the rate, within 0.05 Hz, tested at every rate of the matrix); it claimed a tenth of a hertz at 19 kHz while 1.3 Hz off. The peak is labelled as the sample peak of the engine output.
- `renderOffline` returns exactly the first frames the engine renders, wherever the browser started its processor: under load, WebKit started it at frame 128 and the render began with silence (a wrong hash). The processor marks every frame it renders on an extra channel; the render has a margin of 16,384 frames and fails, with an explanation, if the processor starts beyond it.
- End-to-end tests serve on a free port chosen at each run instead of fixed ports (4392, 4393): two runs (two worktrees, or two packages) never share a server.
- `capture` refuses a channel count below 1 or not whole, and a frame count below 0 or not whole (a fractional count never resolved); `addProcessors` and `loadPatch` name the URL or the module they could not load.
- `WasmEngine.render` no longer allocates: 500,000 renders cause no garbage collection (the previous version caused 100), checked by `test:allocation`, run without instrumentation.
- `WasmEngine` reads every export as unsigned (addresses from 2 GiB on came back negative), checks the number of arguments of each export, explains a module that cannot be instantiated, turns a trap into an `EngineTrap` and never calls a trapped module again, refuses a sample rate that is not a whole number of hertz (48000.5 was silently truncated) and outputs of different lengths (before rendering anything).
- The oracle computes ideal sines at the binary32 frequency the engine plays, as the patch format now states (parameters are binary32): an expectation at 440.1 Hz no longer compares with a frequency the patch cannot express.
- End-to-end tests run one browser at a time: in parallel, on an idle machine slowed down by the system, live captures and clicks timed out at random.
- `interleave` (engine-wasm hash helpers) copies samples bit for bit: a signaling NaN was turned quiet on the way to the hash.
- The determinism ban list covers every `f32`/`f64` method that is not correctly rounded (`atan2`, `exp2`, `hypot`, `cbrt`… were missing), and states the real reason for banning `mul_add`.
- `osc~` keeps its phase within one cycle at any frequency and sample rate: above the sample rate (possible at any rate below 20 kHz, the highest frequency), the phase grew without bound and the output drifted into noise within hours. Rendered samples are unchanged below the sample rate.
- Fresh clones install the conformance oracle's dependencies: `tooling/oracle` is now a pnpm workspace member (a green local check depended on leftovers).
- `cargo xtask check` rejects a coverage report that measured nothing (0 of 0 lines, functions or branches).
- The conformance export directory is emptied before every export, so no WAV file from an earlier run is judged.
- Mutation testing copies only versioned files (`--gitignore=true`).

### Security

- The JavaScript supply chain is checked like the Rust one: `pnpm audit` runs in `cargo xtask check` (the five moderate advisories in development tooling, all in transitive dependencies of Stryker and ESLint, are fixed by pnpm overrides), and a license gate allows MIT, Apache-2.0, BSD-2/3-Clause, ISC and 0BSD for what the apps ship, a wider list for tooling, and one documented exception (sharp's image library, build time only).
- The playground, the roadmap and the engine test bench declare a Content Security Policy: everything from the site itself, no inline script or style, and only `'wasm-unsafe-eval'` where the engine runs. End-to-end tests check on every browser that the page declares it, breaks none of it, and that it is enforced (a blocked image as control). The roadmap's styles are no longer inlined. The roadmap's end-to-end tests serve on a free port too.
- The end-to-end test server serves only the bench, the built package and the conformance cases, patches and references, to this machine only: a path such as `/conformance//etc/hosts` read any file, and any host name was answered (DNS rebinding).
