# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- `cargo xtask mutants <target>`: every mutant of one target, for development: a crate (its name), a Rust file of a crate, a TypeScript package (its directory) or one of its sources, then the gate on that report (the unviable-mutant gate or the TypeScript mutation gate, as for a partial run, except a whole TypeScript package, gated as complete). A file target must exist and not be test code (Rust or TypeScript, fixtures included), and a path is taken only in its plain form from the root.
- `cargo xtask check` refuses, in the prose of the repository (Markdown outside code; the comments and string literals of Rust and TypeScript), the synonyms `GLOSSARY.md` replaces: "node" or "object" for a box, "behaviour" and "colour", "block" for a render quantum ("tap block", and anywhere in the playground). `vocabulary.txt` lists each refused term with the word to use, where it applies and the reviewed contexts where it is allowed (a Web Audio node, a JSON object); an allowance that allows nothing fails too.
- `cargo xtask check` requires every TypeScript source of a package (its tests apart) to be both measured by its coverage and mutated by Stryker, or reviewed in `proof-bypasses.txt` (`not measured`, `measured, not mutated`), from the reports themselves: a source mutated but not measured, a file measured that is no source, a `mutate` glob matching nothing or written in a syntax the gate does not read, and a stale review all fail. So each package's Stryker `mutate` and coverage `include` select the same sources, the roadmap's Astro templates apart (roadmap #15). The register now lists the tool configurations, entry points and browser shells left outside the proofs, each with what proves it instead.
- The render hash is specified (`spec/render-hash.md`: byte layout, byte order, versioning rule, a worked example), with known-answer vectors (`spec/render-hash-vectors.json`: `-0`, a subnormal and a NaN payload among them) that the Rust, TypeScript and oracle implementations are all tested against.
- `roadmap title <text>` sets the board title, the heading of the public roadmap page, which no command could change; the roadmap is now titled "Poyetik".
- Playground: the page warns, before its button, that it plays a continuous tone, so that the volume can be lowered first.
- Seeded property laws for reading patches (`engine-testkit/tests/parse_laws.rs`): arbitrary text, deeply nested documents and thousands of patches with hostile parts (wrong types, extreme ids, ports and numbers, unknown and repeated keys) go through `parse_patch` and `Plan::build` with the real boxes: refused or played, never a panic, and every accepted plan renders finite samples without allocating. Coverage-guided fuzzing follows with roadmap #3.
- Conformance case `sine-19984-at-8k`: 2.5 cycles per sample, the regime where the `osc~` phase increment rounds the most. The `osc~` error bound is now derived per regime (below 1, then 1 to 4 cycles per sample), with its precondition, fewer than 4 cycles per sample at every supported rate, checked by a test; its unit tests compare with an exactly reduced phase.
- `cargo xtask check` checks the history: every commit message follows the convention, and every `feat`, `fix`, `perf` or breaking commit since the rule was introduced updates the changelog. It also requires CI to pin every action to a full commit hash, the Cargo tools to exact versions (which the preflight now requires locally too) and Node.js to `.node-version`.
- `dependencies.txt`: every direct third-party dependency of every crate and package, with the reason it is needed; `cargo xtask check` fails on a dependency not listed (a new crate in a `Cargo.toml`, a new key in a `package.json`) and on a stale entry. "No unexpected dependencies" was claimed but checked by nothing.
- `cargo xtask check` refuses every bypass of a proof unless it is reviewed in `proof-bypasses.txt` (empty): a skipped mutant, an ignored or focused test, a coverage exclusion, a cargo-mutants configuration; and a Stryker configuration with a key that could hide mutants, a negated `mutate` glob or no JSON report.
- `cargo xtask check` checks the history: every commit message follows the convention, and every `feat`, `fix`, `perf` or breaking commit since the gate was introduced updates the changelog. It also requires CI to pin every action to a full commit hash, the Cargo tools to exact versions (which the preflight now requires locally too) and Node.js to `.node-version`.
- The pre-push hook (`cargo xtask pre-push`) refuses a working tree with uncommitted changes and a pushed commit other than the one checked out, so that the check validates exactly what is pushed.
- `GLOSSARY.md`: the words of the project, with the name each takes in the patch format and the code. READMEs for the roadmap, the oracle and the shared policy; `cargo xtask check` now requires a README in every TypeScript package, every part named in the README of its folder and every folder in the root README.
- The shared TypeScript policy (`@poyetik/config`) is itself checked: each lint rule and strict compiler setting is proven, by a fixture that breaks it, to reject exactly what it forbids, with 100% coverage and no surviving mutant; the ESLint configuration is now TypeScript, linted by itself, and a step of `cargo xtask check`.
- `cargo xtask check` starts by checking the platform (macOS or Linux; Windows through WSL2) and every tool it needs, Node.js 22.18 or later included, naming what is missing and how to install it; `cargo xtask list` lists the checks. `.gitattributes` keeps LF line endings everywhere (the git hooks are shell scripts), and `pnpm install` no longer fails outside a git work tree.
- A membership gate in `cargo xtask check`: the `package.json` files tracked by git must be exactly those the version check reads, every TypeScript package must have its checks and reports run, and every crate must take the workspace version. A package added without being wired into the checks now fails it.
- `cargo xtask check` reads the coverage summary and the mutation report of every TypeScript package itself (100% of lines, statements, functions and branches; no surviving or uncovered mutant), from report directories emptied at each run: lowering a package's own threshold, or a package no longer writing its reports, now fails the check.
- `captureEngine` (engine-wasm web API): captures live the first frames the engine renders, from where its processor really started, as `renderOffline` does offline (`OFFLINE_MARGIN` is renamed `START_MARGIN`, shared by both).
- `mutants-equivalent.txt` and a gate in `cargo xtask check`: every TypeScript mutant disabled as equivalent is listed there with its justification; a disable comment that is not listed, a stale entry, or a broader disable (a whole file, every mutator) fails the check.
- The WebAssembly module exports `engine_abi_version`: the interface identity ("PY") and version (1), checked before anything else by the JavaScript side.
- No-allocation proofs beyond single boxes: the plan laws check that rendering any random built plan allocates nothing, and the WASM engine tests check `Engine::process`, `Instance::process` and `engine_process` (at every sample rate of the matrix). The CLAUDE.md claim about an `assert_no_alloc` check, which did not exist, is corrected.
- Seven conformance cases from the test matrix: 8 kHz near and above Nyquist and above the sample rate, 44.1 kHz with a partial last block, 20 kHz at 48 kHz, 19,999 Hz at 384 kHz, and 0 Hz. The Node tests and the four browsers render the whole corpus (each at its own rate) and check it is complete; live captures cover 48 and 44.1 kHz.
- `Renderer::render_into` renders the next frames into a caller buffer, without allocating; it continues exactly like `Renderer::render`.
- `engine-core`: the box contract (`Object`, `ObjectSpec`), strong types (`SampleRate`, fixed 64-frame `Block`, `NodeId`) and the deterministic execution plan (validation, topological sort, cycle detection, allocation-free processing).
- `engine-objects`: the first boxes, `osc~` (sine oscillator, 440 Hz by default) and `dac~` (stereo audio output), and their registry.
- `engine-testkit`: the laws every registered box must respect (metadata, determinism, finite output, no allocation while processing), checked with random inputs from a fixed seed.
- Patch format, version 1 (`spec/patch-format.md`), read by `engine-patch`.
- `engine-core`: `Renderer::render` renders the frames of a plan offline.
- `engine-hash`: canonical SHA-256 hash of a render, cross-checked with an independent implementation.
- `engine-cli`: renders conformance cases to WAV files, checks and blesses reference hashes.
- First conformance case, `sine-440`, checked by `cargo xtask check`; `cargo xtask bless` is the only way to update reference hashes.
- `engine-wasm` (`bindings/wasm`): the engine as a WebAssembly module with a minimal C interface, and its TypeScript glue (`AudioWorklet` processors, main-thread API, offline rendering, live capture), proven bit-identical to the native engine in Node and in Chromium, Firefox, WebKit and mobile WebKit.
- Playground (`apps/playground`, Vite + React): a 440 Hz sine from the Rust engine with an on/off button, a live Canvas 2D oscilloscope and its measurements (frequency, peak, sample rate), tested on Chromium, Firefox, WebKit and mobile WebKit, with accessibility checks.
- `engine-wasm`: `tap` streams the output of a Web Audio node to the main thread; `capture` is built on it.
- Independent conformance oracle (`tooling/oracle`, TypeScript): rereads the WAV file of every case, recomputes its hash with Node's own SHA-256 and checks each channel against its mathematical definition (`conformance/expectations.json`); `engine-cli export` writes those files; both run in `cargo xtask check`.
- `@poyetik/config` (`tooling/config`): the strict TypeScript and ESLint configuration shared by every TypeScript package.
- `xtask`: Miri runs the tests of the engine FFI; the `bindings/wasm` package checks (build, types, lint, 100% coverage, mutation testing, end-to-end tests) are part of `cargo xtask check`.
- `xtask`: `cargo xtask check`, the single quality gate run by the pre-push hook and CI.
- Monorepo layout: `spec/`, `crates/`, `bindings/`, `apps/`, `conformance/`, with one Cargo workspace and one pnpm workspace at the root.
- Public roadmap (`apps/roadmap/`): kanban stored in `board.json`, driven by a CLI, rendered as a static page with collapsible steps.
- Project rules in `CLAUDE.md`.

### Changed

- `cargo xtask check` (the default, which the pre-push hook runs) now mutation tests only the changes: Rust mutants in the lines changed since the merge base of `HEAD` with its upstream, else `origin/main`, else `main` (uncommitted changes and new Rust files included; no change, no mutant; every mutant of a crate whose test code changed, every Rust mutant when a `Cargo.toml`, `Cargo.lock`, `rust-toolchain.toml` or `engine-testkit` changed), and TypeScript mutants through Stryker's incremental mode, which reuses the results of what did not change. The unviable-mutant gate then refuses every unreviewed unviable mutant the run generated, but no longer takes as stale the review of a mutant it did not generate. `cargo xtask check --full` runs every mutant and still refuses stale reviews (both modes run cargo-mutants in parallel jobs, half the machine's threads); CI runs it, and it is required before a release, closing a roadmap ticket and a deep review. A green default check no longer proves a green full check. The pre-push hook passes each pushed commit with the remote ref it updates, and runs the full check when a tag is pushed. Each package's `pnpm check` no longer runs Stryker: xtask runs it as a step of its own (`cargo xtask list` names them), and the `test:mutation` scripts are gone.
- The marker that asks CI to run on a push, `[ci]`, is accepted only alone on a line of a commit message: the commit-msg hook and the history gate refuse it anywhere else, so that a commit naming it in a sentence no longer starts CI unasked.
- The workflow gate accepts exactly two conditions: the upload of the reports after a failure, and the decision that a push runs the check only when its last commit asks for it with `[ci]`; any other condition, or a variant of these, is refused.
- engine-wasm: a malformed render quantum from the tap processor is reported as `invalid message from the processor: render quantum is not an array` instead of `tap block is not an array`: the glossary's word for what a tap delivers.
- The shared lint policy refuses `fetch` (bare, or through `globalThis`, `window` or `self`) outside each package's one checked helper, its file named `fetch.ts`, which refuses a response that is not 2xx and names the URL: a 404 can no longer reach a JSON parser or the WebAssembly compiler as an empty body. The playground loads the engine through its own `fetchOk`, with the same messages as before.
- Every Vitest configuration refuses a focused test (`allowOnly: false`) locally as in CI, where Vitest refused it alone, and the shared lint policy refuses any focused or skipped test or suite, in Vitest and Playwright (`.only`, `.skip`, `.todo`, `.fixme`, `.skipIf`, `.runIf`).
- `std::env::args`, which panics on an argument that is not Unicode, is banned by Clippy: every command-line tool reads `args_os` and refuses such an argument as a usage error.
- Playground: the oscilloscope repaints only while playing; stopped, suspended or failed, it is drawn once (the grid and dashes) instead of being redrawn at the display rate, forever, on a page where nothing plays.
- The plan laws (`engine-testkit`) compare every render with a simple reference renderer, bit for bit, so that a plan routing, summing or handing boxes the sample rate wrongly fails them (a test box outputs its rate); they try different patches at each rate, check that processing block by block gives the same samples as rendering, and measure allocations from the first call on a fresh plan. Property tests run with `engine_testkit::runner`, whose configuration no `PROPTEST_*` environment variable can change.
- Error messages and the patch format specification say "box", the project's word, instead of "node": "box 3: unknown box type", "too many boxes", `[box id, outlet index]`. The JSON key `nodes` is unchanged.
- **Breaking:** offline rendering moves from `Plan` to a new `Renderer`, which owns its plan: `Renderer::new(plan)`, then `render` or `render_into`. `Plan` keeps `process`, one block at a time. Mixing both on one plan used to reorder time silently (a later block returned before the rest of the current one); it no longer compiles. `render_into` copies one channel at a time, as many frames as the current block and the buffer hold, instead of testing every sample.
- The box laws (`engine-testkit`) also try every parameter at `-0.0` and at the smallest subnormal (`1e-45`), where its range accepts them; the long run is documented for what it reveals (late overflow, non-finite output, late allocation), not slow drift, which it has no reference to detect.
- Patch format: port indices range from 0 to 65535, read as 16-bit integers. A larger index was accepted by the native reader and rejected by the WebAssembly one (whose pointers are 32 bits wide), so the same patch failed differently on each target; every target now rejects it while reading.
- The preflight of `cargo xtask check` requires exactly the Node.js release of `.node-version`, the one CI installs, instead of any release from 22.18 on: a green local check means a green CI. `packageManager` pins pnpm with the SHA-512 of its package, so that the bytes downloaded are verified.
- Every crate takes its repository URL from the workspace, the real one (`https://github.com/cgXai/poyetik`) instead of the placeholder `example.invalid` repeated in each manifest; the membership gate requires it, as it requires the workspace version.
- Supply chain: Dependabot proposes, and pnpm installs, a release only once it is a week old (`cooldown`, `minimumReleaseAge`); the `qs` override stays on 6.x (`^6.16.1` instead of `>=6.16.1`); cargo-deny holds `libm` to no feature, so that the tests cannot run other `libm` code than the shipped engine. `cargo xtask check` requires these settings.
- **Breaking (`cargo xtask` output):** `cargo xtask` follows the command-line contract written in CLAUDE.md. Every failure is one `error: …` line on stderr naming the step, the file or the command; its details (every problem a gate found, the expected form of a commit message) go to stdout, instead of several unprefixed lines on stderr. A usage error says what is wrong in one line, `error: unknown command "chek" (see: cargo xtask help)`, instead of printing the whole usage; only `help` prints it, aligned and in the order of its first line. An argument that is not UTF-8 is a usage error instead of a panic (exit 101).
- CI runs on a named OS release (`ubuntu-24.04`, never `-latest`), keeps its Rust cache when a run fails or is cancelled, may run for 180 minutes (provisional), and a failed run uploads every report a gate reads (the oracle's and the shared policy's too, the Rust coverage) and the WebAssembly module; `cargo xtask check` requires all of it.
- The roadmap page shows its columns in classic kanban order, Later, Next, In progress, Done, from left to right; on a phone, where the columns stack, In progress still comes first.
- **Breaking:** the project is named Poyetik. Every package is `@poyetik/…`, and the WebAssembly module's interface identity is now "PY" (`0x5059_0001`): a module built before the rename is refused by the new JavaScript side, and the reverse.
- **Breaking (roadmap CLI):** the steps of a card are steps everywhere, as on the page: the command `task add|done|undo|edit|rm` is now `step add|done|undo|edit|rm`, and the messages say "step". The data file keeps its `tasks` key, unchanged byte for byte.
- The step names of `cargo xtask check` all start with a capital letter (checked), and the engine documents that its output is never clipped or sanitized: the final output stage belongs to the host until the engine defines its own output policy.
- Names say what they hold, in Rust and TypeScript alike: no single-letter names but `i`, `j`, `x` and `y` (Clippy `min_ident_chars`, ESLint `id-length`; a Rust trait implementation's parameters may keep the trait's names, such as `f` in `Display::fmt`, which Clippy does not flag), and in TypeScript no declaration hiding another (`no-shadow`, even before the outer declaration); 256 names were renamed.
- Every named TypeScript item is documented, exported or not (functions, classes and their members, types, module-level constants), as the Rust items already were: the JSDoc rule no longer checks exported declarations only.
- The engine test bench is compiled into `dist/e2e-site/`, not next to its source behind a nested `.gitignore`; the membership gate now refuses any `.gitignore` but the root one.
- The tools shared by several TypeScript packages (TypeScript, Vitest, Playwright, Stryker, ESLint, axe, Node types) have one version each, in the pnpm catalog of the workspace; the Node type definitions follow the Node version the packages require (22.18), not Node 26, and the roadmap no longer allows a newer TypeScript than the others.
- The counting allocator of the tests is its own crate, `engine-alloc-counter`, checked by Miri; `engine-testkit` and the engine and instance modules of `engine-wasm` forbid unsafe code, and `cargo xtask check` fails when any file but the two audited ones lifts the lint against unsafe code.
- Roadmap: only a card in the In progress (`doing`) column has a step in progress; a card waiting in another column shows nothing in progress, and `step done <id>` without a step number fails for it.
- **Breaking:** the oracle and the roadmap CLI follow the same command-line contract as `engine-cli` and `cargo xtask`: exit code 2 for a usage error (the roadmap used 1), one `error:` line naming the file (the oracle's JSON errors did not, the roadmap printed stack traces for unreadable files), and a closed stdout ignored instead of crashing. The contract is written in CLAUDE.md.
- `cargo xtask` exits with 2 on a usage error, names the command and its exit code (or the signal) when a step fails instead of "command failed", and ignores a closed stdout.
- **Breaking:** `engine-cli` follows the command-line contract: exit code 2 for a usage error and 1 when a command fails, each with exactly one `error:` line on stderr. A usage error gives its reason ("unknown command", "unknown option") and points to `engine-cli help`, which prints the usage on stdout; a failure names the file at fault, the case or the patch (`prepare_case` and `render_case` return a `CaseError` telling them apart, and `CliError::Usage` carries its reason). An argument that is not UTF-8 is a usage error instead of a crash. A closed stdout (`| head`) no longer turns a success into a failure.
- The playground shows every state the player reaches: starting, playing, paused by the browser (with Resume), stopping, failed (with the reason next to the button and linked to it), instead of showing "Playing" while silent. Starting twice or stopping during a start is safe. The sound fades in and out over 20 ms and the device is released only after the fade, on the audio clock: no click. A browser lacking a secure page, Web Audio, AudioWorklet or WebAssembly is told what is missing. The button keeps the keyboard focus across transitions (`aria-disabled` instead of `disabled`) and looks different while it stops the sound.
- **Breaking:** `LoadedPatch` (engine-wasm web API) is a class only `loadPatch` creates, with its own copies of the bytes: a patch the engine did not check cannot be passed to an engine node. `createEngineNode` takes an `onFailure` callback and returns `{ node, ready }`: the processor tells the main thread whether it loaded the patch, and reports a later failure (a trap) once, instead of falling silent unnoticed. `renderOffline` rejects instead of returning silence when the processor fails.
- **Breaking:** conformance expectations no longer declare a tolerance (`max_error`, refused if present). The oracle derives the largest allowed distance from the ideal sine, term by term (binary32 output rounding, binary64 phase accumulation over the case length, evaluation), and computes its reference with an exact phase reduction, so it stays exact however long the case (up to 2^29 frames). The bound went from a guessed 1e-6 to 2.98e-8 at 1 s; a phase computed in binary32 (1.7e-3) or a gain off by 5e-7 is rejected. The `osc~` tests use the same bound.
- **Breaking:** the patch of each conformance case is its own file, `conformance/patches/<name>.json`, and every runner (native CLI, Node tests, browser bench) passes its bytes to the engine unchanged. The runners used to rewrite the patch from a parsed copy, which could hide differences (a repeated parameter was silently merged; JavaScript writes `-0` as `0`). `engine-cli render` takes the case and the patch files. A case without its patch, or a patch without its case, is an error.
- The playground plays the same document as the sine-440 patch of the conformance corpus (compared after parsing by a test), whose render has a reference hash.
- **Breaking:** `Patch` is a validated type, built only by `Patch::new`: box ids are unique, cables are never repeated, and a patch holds at most 65,536 boxes and 262,144 cables. The cables into an inlet are summed in a fixed order (source id, then outlet), whatever the order of the document. The patch reader also refuses documents over 16 MiB and a parameter named twice in one box.
- **Breaking:** `Renderer::render` continues exactly where the previous call stopped (rendering `a` then `b` frames equals rendering `a + b`), and returns `CoreError::RenderTooLong` instead of failing when the samples cannot be held in memory.
- Execution order is computed with Kahn's algorithm, in O((N + E) log N) instead of O(N²·E): a patch of 16,000 boxes is ordered in milliseconds instead of seconds. The order is unchanged.
- Error messages name the faulty element once and say what is expected ("box 2 is declared twice", "invalid sample rate: 5 Hz (supported: 8000 to 384000 Hz)").
- The conformance CLI refuses a case whose patch has no audio output, instead of rendering nothing.
- The box laws (`engine-testkit`) run at every sample rate of a shared test matrix (8 kHz to 384 kHz, including 44.1 kHz), with special inputs (signed zeros, subnormals), a long run and parameters away from their default; a box that fails at any of them fails the laws. The matrix is also published as `conformance/test-matrix.json` for the TypeScript tests.

### Removed

- **Breaking:** `engine-cli`'s `Prepared::rate`: nothing used it, and no test could tell a wrong rate from the right one.

### Fixed

- Stryker could read a configuration the gates never checked: run without a file, it takes `stryker.conf.json` (and its `.js`, `.mjs`, `.cjs` variants) before `stryker.config.json`. Every run of xtask now names `stryker.config.json`, a package script may run Stryker only as `stryker run stryker.config.json`, and the scope gate requires every source it should mutate that has statements to appear in the mutation report, or to be reviewed in `proof-bypasses.txt` (`mutated, no mutant reported`: the playground's settings, numeric constants only).
- Ignored tests can no longer leave a proof: the Rust tests, coverage and mutation testing run them too (`--include-ignored`), and the bypass gate refuses the doc tests that never run (`ignore`, `no_run` fences). A `cfg` only a coverage build sets cannot compile elsewhere, so the gate refuses lifting the lint of unexpected `cfg`s and declaring an expected one (a manifest's or a build script's `check-cfg`, `Cargo.toml` files now read). The TypeScript coverage ignore comments are found whatever their spacing, line breaks and case, `node:coverage` and the `ignoreClassMethods` option included, in every source extension (`.cts`, `.cjs`, `.jsx` too).
- The roadmap runs every Astro command (`astro check`, `build`, `dev`, `preview`, and the preview of the end-to-end tests) with `ASTRO_TELEMETRY_DISABLED=1`: a check no longer sends telemetry over the network nor writes in the user's home.
- The roadmap CLI refuses an empty `ROADMAP_FILE` with one error line naming the variable, instead of taking it for a path (`error: cannot read : ENOENT`).
- The oracle reads `expectations.json` with exactly the documented fields at every level (`sample_rate`, `frames` and `channels` for a case; `frequency`, `amplitude` and `phase` for a sine): an unknown field, a typo included, was ignored.
- The oracle refuses a WAV file whose last chunk has an odd size and no pad byte, which RIFF requires after every odd-sized chunk; it was accepted.
- The oracle reads a case file as `engine-cli` does, and the Node tests of the engine read the corpus through the oracle's parser: exactly the fields `sample_rate` and `frames`, a sample rate in the engine's range (8 to 384 kHz), whole numbers written without fraction or exponent (`100.0` and `1e2` are refused). It accepted an unknown field, a rate of 5 Hz or above 32 bits, and `"frames": 100.0`, which `engine-cli` refuses. Every file it reads is read with a size limit, never more than one byte past it, and only from a regular file (a case 64 KiB, `references.json` and `expectations.json` 1 MiB, a WAV file what its RIFF header can declare): a FIFO made it hang and a huge file was read whole. A file it cannot read is named with its error code (`cannot read <file>: ENOENT`) instead of Node's sentence repeating the path. `conformance/invalid/cases/` holds a case for each of these refusals, and a case file above 64 KiB, which `engine-cli`'s corpus test now reads through its size limit too.
- The roadmap CLI with no command is a usage error (`error: expected a command (see: roadmap help)`, exit code 2) instead of printing the help with exit code 0, as the command-line contract requires; its help starts with a lowercase `usage:`, as the other tools'.
- engine-wasm: a module whose `engine_block_size` returns 0 is refused with a `ModuleError` when the engine is created, instead of looping forever at the first render.
- engine-wasm: a NaN on the marker channel is reported at the frame it is found, instead of frame -1.
- engine-wasm: `renderOffline` refuses a negative, fractional or NaN number of frames with a `RangeError` before rendering, as `capture` and `captureEngine` do (one shared check), instead of failing later with a false "the engine stopped".
- engine-wasm: `renderOffline`, `capture` and `captureEngine` no longer wait forever. `renderOffline` decides from the marker channel once the render ends, so a processor the browser never starts during the render is the documented "started too late" error; a capture fails when its context closes, or when its source stops (the tap processor now posts once that its input went from present to empty: an engine that failed, a source that ended). `tap` ignores its source stopping.
- Each crate's coverage is measured from an emptied coverage build: an object left by an earlier measurement (the same crate compiled as a dependency of another) entered the report as a second copy of its code, never run, and halved its coverage.
- The oracle follows the stream part of the command-line contract, like the Rust tools: a broken stderr no longer changes its exit code, and a stdout error other than a closed reader is one `error: cannot write to stdout: <code>` line and exit code 1 (never hiding a usage error's 2) instead of a stack trace.
- The oracle reports a usage error as one line, `error: <reason> (see: oracle help)`, as the command-line contract requires, instead of printing its usage on stderr with no `error:` prefix and no reason; `oracle help` prints the usage on stdout.
- The oracle's error bound is derived regime by regime of cycles per sample (below 1, and from 1 to 4, where the phase additions are exact), and an expectation's frequency must lie in [0, 4 × sample rate), the domain where the bound holds; the previous derivation was wrong from one cycle per sample on, and the 2 to 4 cycles regime (19,984 Hz at 8 kHz) is now tested.
- The oracle's error bound no longer fails a correct render of a very quiet sine (amplitude below 2^-125, whose samples are subnormal), and an expectation's start phase must lie in [0, 2π), the range the bound is derived for.
- The oracle reads the duration of a case file in the same domain as its expectations, 1 to 2^29 frames: a longer case, whose reference would not be exact, is rejected instead of being judged.
- The oracle rejects an expected frequency that is not exactly a binary32 value. It rounded the number `JSON.parse` had already rounded to binary64, a double rounding one ulp away from the engine's correct rounding for a text near a binary32 midpoint, and its bound would then have failed a correct render.
- The roadmap page draws its own keyboard focus ring on a card's steps toggle, the same in every browser, instead of each browser's default; tests reach it with Tab, open and close the steps with Enter and Space, and check the ring's style, width and contrast.
- Roadmap page: each column heading reads its count with a unit for screen readers ("In progress 2 cards"), the card lists keep their list role in WebKit, which drops it from lists without bullets, and a word longer than a card is wide wraps instead of pushing the card out of its column.

A line naming the lint is exempt only when it is exactly the attribute forbidding or denying it: a trailing comment saying `deny(...)` no longer hides an `expect`.

- Rust coverage is measured crate by crate, each by its own unit tests (`cargo llvm-cov --lib` per crate of `RUST_CRATES`, and each binary's `main.rs` by its crate's tests), as CLAUDE.md requires: the single workspace measurement counted a function as covered when any test binary, another crate's or an integration test, covered it. The gate names every file that is not fully covered with its counts and the command showing its lines, and refuses an empty report or a file of another crate; a fixture crate proves the gate refuses a path only an integration test reaches. The membership gate requires the tracked crates to be exactly `RUST_CRATES`.
- README problems are a step of their own in `cargo xtask check` ("Every part described in a README"): they stayed hidden while the membership gate failed, then appeared under its name, and a folder without a README was reported once per part it holds. The version step and the history step say which changelog rule each enforces.

- The TypeScript packages are listed once in xtask (`PACKAGES`): their check steps, the report directories emptied and read, the manifests checked for the version and the license filter of what ships all derive from that table. The membership gate claimed that a package it knew had its checks and reports run, but these came from five hand-written lists, so a new package would have been checked by none of them.

The history gate reads each recorded message as it is, instead of skipping a first line starting with `#` as if it were a git comment.
- The pre-push hook accepts an annotated tag of the commit checked out (`git push --follow-tags`): git hands the hook the tag object, which the check compared with the commit and always refused, with advice that could not work. Each pushed object is now resolved to its commit first.
- `cargo xtask` says why a command failed: its exit code and the error line it wrote (git's `fatal:`, cargo's `error:`), or the signal that stopped it by number and name, naming the command once; it used to drop the reason ("`git log …` failed"), print the command twice, and say only "stopped by a signal". The preflight no longer calls every failing tool "missing": it gives the tool's own reason, then how to install it.

### Security

- The oracle prints every verdict and error line safely, like `engine-cli`: what it quotes from the corpus (a case name or JSON key, a WAV chunk id, the JSON parser's excerpt of a file) has its control, bidirectional and line-separator characters escaped as `\u{..}` and is cut after 1,000 characters (`oneLine`). A crafted key or chunk id can no longer drive the terminal or split a `FAIL` verdict into two lines.
- The roadmap CLI prints every error as one safe line, like `engine-cli`: what it quotes (an argument, a field of `board.json`, the JSON parser's excerpt of the file) has its control, bidirectional and line-separator characters escaped as `\u{..}` and is cut after 1,000 characters (`oneLine`). `show $'1\nerror: forged'` can no longer forge a second error line, nor a board column holding ESC drive the terminal. A text of the board (title, card title, description, milestone, step) may no longer hold such a character, whether read from `board.json` or typed on the command line: it is refused, not escaped, since the page and the listings show it as it is.
- Playground: the build fails when the page lacks the element its Content Security Policy is inserted after, instead of silently building a page without a policy; the insertion is now in `csp.ts`, under coverage and mutation testing.
- `engine-cli` prints every error as one safe line: control, bidirectional and line-separator characters coming from a patch (a box or field name) are escaped as `\u{..}`, and the line is cut after 1,000 characters. A crafted patch can no longer drive the terminal or forge a second error line. Every line it prints on stdout is made safe the same way (each line passes through `engine_patch::safe_message`; only the usage of `engine-cli help` is printed as is): a case name, a box type quoted by `check`'s `FAILED` line, or a key or value of `references.json` could forge an `ok` line on stdout and drive the terminal, and a line had no length limit.
- **Breaking (engine-wasm interface, version 2, `0x5059_0002`):** the module exports `engine_max_patch_bytes`, the 16 MiB limit of the patch format, and `WasmEngine.create` refuses a longer patch with a `PatchError` ("patch too large: … bytes (at most …)", the engine's own words) before asking the module for memory: a huge patch grew the module memory, which is never given back, before the engine refused it. A module of version 1 is refused by the new JavaScript side, and the reverse.
- engine-wasm: the explanation of a rejected patch, which JavaScript receives as `PatchError.detail`, is made safe the same way: one line, control and bidirectional characters escaped, at most 1,000 characters. `engine_patch::safe_message` is the one function both use (`engine-cli` no longer exports `MAX_ERROR_CHARS`; the limit is `engine_patch::MAX_MESSAGE_CHARS`).
- The JavaScript supply chain is checked like the Rust one: `pnpm audit` runs in `cargo xtask check` (the five moderate advisories in development tooling, all in transitive dependencies of Stryker and ESLint, are fixed by pnpm overrides), and a license gate allows MIT, Apache-2.0, BSD-2/3-Clause, ISC and 0BSD for what the apps ship, a wider list for tooling, and one documented exception (sharp's image library, build time only).
- The playground, the roadmap and the engine test bench declare a Content Security Policy: everything from the site itself, no inline script or style, and only `'wasm-unsafe-eval'` where the engine runs. End-to-end tests check on every browser that the page declares it, breaks none of it, and that it is enforced (a blocked image as control). The roadmap's styles are no longer inlined. The roadmap's end-to-end tests serve on a free port too.
- The end-to-end test server serves only the bench, the built package and the conformance cases, patches and references, to this machine only: a path such as `/conformance//etc/hosts` read any file, and any host name was answered (DNS rebinding).

### Fixed

- Oracle: a case, reference or expectation file that is not UTF-8 is refused with one `error:` line naming it, as the engine's own reader refuses it; a byte that is not UTF-8 used to be replaced and the file read anyway.
- engine-wasm: a malformed message from a processor (an engine message or a render quantum from a tap) is reported as "invalid message from the processor", no longer as "invalid processor options".
- engine-wasm: when the engine traps in the browser, the failure reported to the main thread now includes the trap itself ("RuntimeError: unreachable", "memory access out of bounds"), the only clue a module built with `panic = "abort"` gives.
- engine-wasm: `interleave` refuses channels of different lengths instead of padding or cutting them, and `renderHash` refuses a rate that is not a 32-bit unsigned integer (44100.5 was hashed as 44100, -1 as 4294967295), a channel count that is not a whole number, and samples that are not whole frames: a hash is a proof, never computed over something else than what was asked.
- engine-wasm: rendering on the audio thread no longer allocates before V8 optimizes it: whole blocks are copied at once through views of the module memory made once, and no field holds a boxed number. `pnpm test:allocation` now drives the real engine processor from a fresh instance, also with V8's interpreter alone, at every host buffer size of the matrix; CLAUDE.md states what it proves and the known deviations.
- engine-wasm: a block the module places outside its memory, or at an unaligned address, is a `ModuleError` and the engine stops, instead of being read as silence.
- **Breaking (engine-wasm web API):** the marker channel counts the frames the engine renders (1, 2, 3…) instead of holding 1.0, so a live capture or an offline render now fails when the capture started after the engine (it returned shifted frames), when the engine stopped before the end (it returned a silent tail as success, whatever the order of the messages), or when the channel holds no marker; the marker is read in place, no longer copied into a JavaScript array (136 MB for 10 s at 384 kHz). `createEngineNode(…, true)` returns a `MarkedEngineNode`, the only engine node `captureEngine(context, engine, frames)` accepts: it no longer takes the channel count. Both refuse more than `MAX_MARKED_FRAMES` frames, the most the marker counts exactly.
- engine-wasm: creating an engine node no longer uses `Promise.withResolvers`, which Safari before 17.4 and Firefox before 121 lack: they now reach the playground's explanation of what is missing instead of a `TypeError`. The shared lint configuration bans it.
- Playground: starting the player no longer uses `Promise.withResolvers`, which Safari before 17.4 and Firefox before 121 lack: those browsers now reach the explanation of what is missing instead of a `TypeError` (the shared lint configuration bans it).
- engine-wasm: `pnpm build:wasm` and `pnpm test:reproducible` follow the command-line contract: a failed or missing cargo is one `error:` line (exit code, signal, or why it could not run) instead of a Node stack trace, and the problems of a build that is not reproducible are listed on stdout under one `error:` line. Both are now tested, with 100% coverage and no surviving mutant, around thin entry points; `test:reproducible` prints the SHA-256 of the module, to compare builds across machines.
- engine-wasm: the test bench server refuses a port that is not a whole number from 1 to 65535 with one `error:` line and exit code 2, instead of a stack trace; its port parsing and content types are tested functions of `e2e/routes.ts`.
- engine-wasm test bench: a missing build, case or patch fails with the URL and the status (`GET /conformance/cases/x.json: 404`) instead of a JSON or WebAssembly error about an empty body.
- engine-wasm: the README's command to open the test bench works (`ENGINE_WASM_E2E_PORT=4392 pnpm bench`): it builds the bench page and starts the server, and it is the very command the end-to-end tests start.
- engine-wasm test bench: the Content Security Policy test could not fail on Firefox (it looked for console text Firefox words differently) and had no control. It now listens to the page's own violation reports and to console errors while rendering offline and capturing live, checks the declared policy, and proves enforcement with a blocked image. It found a real violation: Firefox's request for `/favicon.ico`, blocked by the policy; the bench now has its own icon, allowed by `img-src 'self'`.
