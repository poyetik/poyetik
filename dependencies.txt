# The dependency register: every third-party crate and npm package a part of the
# repository depends on directly, with the reason it is needed. Parts of the repository that depend on
# each other (path and `workspace:` dependencies) are not listed.
#
# Adding a dependency means adding its line here first, with its reason (see CLAUDE.md,
# "Technologies and dependencies"): as few as possible, mainstream and well maintained; the
# local design notes keep only the strategic reasons.
# Format: `<crate or package directory>: <dependency> (<kind>) -- <reason>`, the kind being
# Cargo's (`normal`, `dev`, `build`) or the package.json field.
# A reason starting `bit-defining: ` marks a crate whose code computes output samples or hashes,
# or the values they are computed from: every normal or build dependency of the audio library
# is one, and each is pinned to one exact version (`=X.Y.Z`, checked for these direct
# dependencies), its updates following spec/engine-design.md decision 29. The code they reach
# in turn (every crate Cargo.lock resolves for them) is fixed by Cargo.lock, not by a pin,
# and proven by the render hash vectors, conformance and the
# fingerprints: a change of one of them in Cargo.lock is an update too.
# `cargo xtask check` fails on any direct dependency not listed, and on any stale entry.

audio-battery: serde_json (dev) -- reads the shared test matrix, conformance/test-matrix.json, which the TypeScript tests read too
audio-battery: sha2 (normal) -- bit-defining: hashes a box type's outputs over the fixed battery into its fingerprint, recorded beside the conformance references
audio-cli: serde (normal) -- reads the conformance case files into typed values, refusing unknown fields
audio-cli: serde_json (normal) -- parses the case files and writes the reference hashes
audio-core: libm (normal) -- bit-defining: the math functions of the engine's math layer (sine, floor), deterministic and portable, identical on every target where std's are not; boxes reach them only through the layer
audio-core: serde_json (dev) -- reads the shared test matrix, so the unit tests run at every sample rate of conformance/test-matrix.json
audio-fpenv: serde_json (dev) -- reads the conformance cases and their reference hashes, rendered under every forced host mode
audio-hash: serde_json (dev) -- reads the shared known-answer vectors of spec/render-hash-vectors.json
audio-hash: sha2 (normal) -- bit-defining: the SHA-256 of a render, without std, the same on every target
audio-boxes: libm (dev) -- the exact references of the tests (sine, exponent, logarithm), computed apart from the math layer of the boxes they check
audio-boxes: serde_json (dev) -- reads the shared known-answer vectors of spec/measurement-vectors.json (the error bound of a sine)
audio-patch: serde (normal) -- bit-defining: reads the patch format into typed values, refusing unknown fields
audio-patch: serde_derive (normal) -- bit-defining: generates the patch reader's deserialization code (the fields read, unknown ones refused), pinned directly since serde requires it only as 1
audio-patch: serde_json (normal) -- bit-defining: parses patch documents, and so the parameter values a render computes from
audio-testkit: libm (normal) -- deterministic math functions (sine, cosine, logarithm) for the measurements, identical on every target where std's are not
audio-testkit: proptest (normal) -- property tests of the box and plan laws, from a fixed seed
audio-testkit: serde_json (dev) -- reads the shared known-answer vectors of spec/measurement-vectors.json
visual-hash: serde_json (dev) -- reads the shared known-answer vectors of spec/image-hash-vectors.json
visual-hash: sha2 (normal) -- the SHA-256 of a sequence of images, without std, the same on every target
xtask: proc-macro2 (normal) -- the Rust tokenizer of the gates that read Rust code (comments nested as rustc nests them, doc comments as prose, every literal whole), its own lexer only: its build script reads only `rustc --version`, no compile probe, no procedural macro; already in the lock through serde_derive
xtask: serde_json (normal) -- reads the coverage, mutation and license reports, the Cargo metadata and the package manifests
