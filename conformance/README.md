# conformance

The **conformance corpus**: every target and every SDK must reproduce these render hashes exactly.

| Path | Contents |
|---|---|
| `cases/<name>.json` | Reference cases: a sample rate and a duration, from 1 to 2^29 (536,870,912) frames |
| `patches/<name>.json` | The patch of each case, in the patch format. Every runner (native, Node, browsers) gives the engine the bytes of this file unchanged, never a parsed and rewritten copy |
| `invalid/cases/<name>.json` | Case files every reader must reject, one fault each (a duration of 0 frames or above 2^29, or not an integer; a sample rate below the engine's range, above 32 bits, or written as a string; an unknown field; a file above 64 KiB): the shared rejection corpus, which the tests of the engine CLI and of the oracle each read whole through their size-limited file reading, refusing every file |
| `test-matrix.json` | The shared test matrix: the values each dimension of the environment is tested across (the precisions, by their widths in bits, among them), read by the Rust and TypeScript tests |
| `references.json` | The expected render hash of every case in each render format (`spec/render-hash.md`): `binary64`, `binary64-as-binary32` (what a browser's audio thread is given) and `binary32`, each rendered in the strict arithmetic mode |
| `algorithms.json` | What the references were blessed under (`spec/engine-design.md`, decision 29), as `cargo xtask bless` recorded it with them: the render hash version, the render rules version, the fingerprint of every box type at each algorithm version blessed (with the version of the battery that computed them), and the algorithm version of every box type each case uses. The check refuses a case whose box types are at other versions (a new version needs new references), another render hash or render rules version, and a fingerprint changed at a recorded version; a reference mismatch under the same versions means bits changed without a new version |
| `expectations.json` | What every case must sound like, independently of any hash: for each channel, the ideal signal. The largest allowed distance from it is derived by the oracle (output rounding, phase accumulation, evaluation), never declared |

- `cargo run -p engine-cli -- check conformance` renders every case natively in every render format and compares the hashes; `cargo xtask check` runs it with `--spent <record>`, the spent record (`algorithms.json` as `main` holds it, at the merge base of xtask's `SPENT_BASES`), and also refuses a fingerprint other than that record holds at a version both hold, whatever wrote the record.
- **`references.json` and `algorithms.json` only change through `cargo xtask bless`**, and the commit must explain why the hashes or the versions changed. The check reads both only exactly as bless writes them (a hand edit or a repeated key is refused). Bless itself refuses, writing nothing (`spec/engine-design.md`, decision 29): a reference of an existing case that changed while its box types' versions, the render rules and the render hash stayed as recorded, or whose case the record does not hold; a box type or the render rules at a lower version than either record holds; a box type's fingerprint changed at a version spent on `main` (one the spent record holds: versions first blessed on the branch may be blessed again, pushed or not); a battery change but with `--battery-changed`, in a bless of its own (with another change on the branch, the battery change is blessed alone first, as the refusal's hint says); and a directory missing either file but with `--from-nothing`. A case whose own files changed on purpose is named with `cargo xtask bless --case-changed <name>` (repeatable), and the commit says why.
- `cargo run -p engine-cli -- render conformance/cases/<name>.json conformance/patches/<name>.json --wav <file.wav>` writes a case as a WAV file to listen to (`--format <format>` chooses the render format; binary64 by default, 64-bit float samples).
- `cargo run -p engine-cli -- export conformance target/conformance` writes the WAV file of every case in every render format, `<case>.<format>.wav` (64-bit float samples for `binary64`, 32-bit otherwise); the independent oracle (`tooling/oracle`) then rereads them, recomputes their hashes and checks `expectations.json` against the error bound of each format. `cargo xtask check` runs both.
- Every case needs its patch, a reference hash, its algorithm versions and expectations, and every patch its case: the engine CLI fails on anything missing, the oracle on a missing case file, reference, expectation or WAV file (it reads neither the patches nor `algorithms.json`).
- Size limits, checked while reading by the engine CLI and the oracle alike (never more than one byte past them, and only from a regular file): a case file holds at most 64 KiB, a patch file 16 MiB (the limit of the patch format), `references.json` 1 MiB, `expectations.json` 1 MiB, an exported WAV file 4 GiB + 7 bytes (what its 32-bit RIFF size can declare). The engine CLI reads the case, patch and references files, and `algorithms.json` and the spent record (`--spent`), at most 1 MiB each; the oracle reads the case, references, expectations and WAV files.
