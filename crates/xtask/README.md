# xtask

The project's automation: `cargo xtask check` and the commands of the git hooks (`cargo xtask help` lists every command). What each check proves, and what the default check does not, is in the crate's documentation (`cargo doc -p xtask`) and in the root `CLAUDE.md`, section CI.

## Measured choices of the check's speed

The default check is run before every push, so its time decides how often it runs. Every change made to shorten it is recorded here, one entry each: when, what was measured with its numbers, what was kept and why, what was rejected and why, and how to measure again. The order of the reasons is the project's: **no guarantee is traded for speed** (each kept change carries its own argument that it changes no outcome, since comparing the outcomes of one run is only a smoke test: almost every mutant dies on the first failing test), and the development environment stays portable (nothing here depends on one operating system's setting or tool). `cargo xtask check --full`, which CI runs, keeps its strength. The engine's own measured choices are in `spec/benchmarks.md`, "Measured design choices".

**How it was measured.** On the maintainer's Mac (10 cores, 16 GB), a fixed slice of the Rust mutants, `--shard 3/20 --sharding=round-robin` of cargo-mutants with the check's own options, about 110 mutants, run on a clean clone, one heavy run at a time, the forms compared alternated (A, B, A, B); per mutant, the build and test phases from cargo-mutants' report; the peak memory of the compilers, linkers and cargo-mutants sampled every second. The machine was in use: single runs vary by about 10%. The numbers below are those runs', on 2026-11-10; to measure again, run the same slice with and without the change, at least twice each, alternated, and compare the outcomes mutant by mutant as well as the times.

- **Mutant builds without debug information** (`MUTANT_BUILD_CONFIG`, every cargo-mutants run). Measured with debug information (Cargo's default), with `debug = false` and with line tables only, on 111 mutants at 5 jobs, in the order A1 B1 L1 A2 B2 L2:

  | Run | Setting | Wall time | Job time | Mean build of an xtask mutant |
  |---|---|---|---|---|
  | A1 | default | 182 s | 724 s | 3.42 s |
  | B1 | `debug = false` | 145 s | 576 s | 2.75 s |
  | L1 | line tables only | 162 s | 624 s | 3.14 s |
  | A2 | default | 179 s | 697 s | 3.63 s |
  | B2 | `debug = false` | 171 s | 692 s | 2.97 s (a foreign load on the machine) |
  | L2 | line tables only | 164 s | 637 s | 3.27 s |

  The same outcome for every mutant in all six runs. Kept: `debug = false`, the fastest builds of xtask's mutants (about 60% of all mutants) in both pairs, about a tenth less job time. The argument that it changes no outcome: compared on every compiler command line of `cargo test --no-run -v`, it changes only the debug-information options and the hashes Cargo names outputs with, and no code reads a backtrace's file and line (reviewed). Rejected: line tables only, close but slower to build xtask; the default.
- **No unit-test build of a binary's `main.rs`** (`test = false` on the binaries of `engine-cli` and xtask, `untested_targets_gate`). Their test harness held no test (each root declares no module, and test code lives only in declared `*_tests.rs` files and `tests/`), so every build of a mutant of those crates compiled and linked one program for nothing. Not measured alone: the slice above holds too few of those builds to resolve one compile and one link each. Kept, with a gate that refuses `test = false` on a target whose root declares a module.
- **One integration test program for xtask** (the binary's tests and the hooks' tests, two modules of `tests/binary.rs`). One compile and one link less per mutant of xtask; nine tests before and after, each unchanged. Not measured alone, for the same reason.
- **Mutation jobs: half the machine's threads, unchanged** (`mutation_jobs`). Measured on 115 mutants without debug information, in the order 5, 3, 4, 6, 5 jobs: wall time 158, 155, 165, 149 and 174 s, job time 634, 376, 547, 737 and 702 s, peak memory 2.3, 2.6, 2.5, 4.8 and 2.5 GB; the same outcomes in all five. No knee: the wall time is flat within the noise of the two 5-job runs, while the job time doubles from 3 to 6 jobs (contention). Kept: half the threads, from `available_parallelism`, valid on every system. Rejected: memory as an input of the formula (the standard library has no portable reading of it, and a reading per system breaks portability; about 0.5 GB per job was measured, so half the threads fits any machine with 1 GB per thread). Three jobs gave the same wall time at half the load; deciding needs a larger slice (roadmap #24 step 32).
- **The default check runs its steps cheapest first** (`cheapest_first`): the gates, the Rust checks, coverage, Miri, the TypeScript packages, then the Rust mutation testing, so that a failing gate, lint or test is reported before the mutation testing, about eighty minutes earlier on a change of the whole branch. Not a measurement but an order: the argument is that each part of the full check runs alone in CI after only its own preparations, so no step depends on another part's. `--full` keeps its order.
- **Widening per crate** (`widening`, `lock_widened`). A change of a shared input (a crate's manifest, a crate of shared test code, `Cargo.lock`) widens the mutation testing to the crates it reaches, where it widened to every Rust mutant. Not measured: it saves nothing on a branch that changes the root `Cargo.toml` (which still mutates everything), and helps the commits after it. Checked against what the compiler reads: after `cargo test --workspace --no-run`, every dep-info file of a workspace target names, among the repository's files, only files of the crate's closure, its declared test data and the root `Cargo.toml`.
- **xtask tested on its fixtures only**. Its tests read the real repository (every Rust source, the workflow, `cargo metadata`), so its declared test data was the whole repository and every change re-mutated all of xtask's mutants; those reads were the gates themselves, which every check runs as steps. Its tests now read fixtures, its test data being the hooks it runs. Not measured: a change outside xtask no longer widens to its mutants, which were about 1,200 of the 2,214 Rust mutants of the branch's first default check.
- **The mutation proof record** (`ProofRecord`). A default check that passed on a clean tree records what it proved; a later default check of the same base skips every crate whose inputs are byte-identical since. Before it, every default check of a block branch mutated the whole diff since the merge base, widened to every Rust mutant once the shared test crate changed: 1,888 mutants for any change (2026-11-09). Not a measurement of speed but of what is repeated; its soundness is argued on its type (a record never changes what the default check proves).
- **A test timeout that scales with the jobs** (`mutant_timeout_args`). Not a speed change but a false failure removed: a mutant caught by a fast test whose program still ran its slow tests to the end was reported as a timeout under parallel jobs (two of `engine-testkit`, about 30 s against 22 s allowed at 5 jobs); the timeout is now multiplied by the jobs, and a hanging mutant is still stopped and fails the check.
- **Rejected after measuring.** Removing the second build of the WebAssembly module (the package's own `pnpm check` builds it again): 8.7 s the first time, 1.2 s when repeated, not worth a step the package's CI job and standalone check need.
- **Rejected by argument, unmeasured.** Turning off xtask's doc tests (no caught mutant reached them, about a second per run: not worth a proof bypass); `nice` (not portable, and it raises the risk of false timeouts); cargo-nextest (no doc tests, and a set of caught mutants that differs from `cargo test`'s, so the default check would claim more than `--full` shows); a higher optimization level (it may remove heap operations the counting allocator must see); another linker or a compiler cache through flags or a wrapper (refused by the preflight and the Cargo configuration gate); skipping cargo-mutants' unmutated baseline, changing the test threads, running the TypeScript steps beside the Rust mutation testing, sharing target directories across steps.
