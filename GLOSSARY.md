# Glossary

The words of the project, with the name each one takes in the patch format and in the code. One concept, one word: when a document or a message needs one of these concepts, it uses the word of this list. The names in the code that still differ (`Object`, `kind`, `node`) are kept until the public engine API takes its final names (#32 step 15); the patch format's own naming conventions are #3 step 3. This table maps them meanwhile.

## Patches and the engine

| Word | Meaning | Patch format | Code |
|---|---|---|---|
| **patch** | A graph of boxes connected by cables: what a user builds and the engine plays | the JSON document (`spec/patch-format.md`) | `Patch` (`audio-core`), parsed by `audio-patch` |
| **box** | One processing unit of a patch (an oscillator, an output) | an entry of `nodes` | `Node` (a box placed in a patch, `audio-core`); its behavior implements the `Object` trait (`audio-core`), and, with parameters, `Driven`, its second body for driven parameters (given `DrivenValues`, checked against its ranges), registered in `audio-boxes`; a plan holds each as an instance of its `Dispatch` type (see plan) |
| **box type** | What a box is, by name (`osc~`, `dac~`) | `nodes[].box` | `Node::kind`; `ObjectSpec` describes it |
| **description** | What a box type says of itself: its name, its description text (what it does, in a sentence; a port and a parameter have one too), its ports, its parameters, its versions; across a module boundary, the bytes of section 4 of `spec/box-contract.md` | none | `ObjectSpec` for a built-in box type, checked by the box laws (`audio_testkit::check_description`); `host::Description` reads a module's (refused with a `DescriptionError`) |
| **box id** | The identifier of a box, unique in its patch; also orders execution among boxes ready at the same time | `nodes[].id` | `NodeId` |
| **parameter** | A named number set on a box (`frequency`); unset ones take their default | `nodes[].params` | `ParamSpec` describes it, built by `param!` (checked when compiled) or the checked `ParamSpec::new` (refused with a `ParamSpecError`), `Node::params` holds the patch's values; `ParamValues` (`audio-core`) owns a box's values with the box type they were built against (`ParamValues::of`, refused with a `ParamError`, or `ParamValues::defaults`), a box type is given them as an array of its own length (`Create<K>`), and a box in a plan too (`Driven::set`), the engine holding them as `Params`, a borrowed view, and taking them apart for it (`Params::array`, `Typed`) |
| **inlet**, **outlet** | The inputs and outputs of a box, numbered from 0 | `connections[].to`, `connections[].from` | `PortSpec` |
| **instantaneous response** | What a box type declares of how a box's output at a frame depends on its input at that frame: none, linear, or non-linear with its derivative, so that the engine can resolve a loop without delay through it (`spec/engine-design.md`, decision 3) | none | `host::Response`, its codes in a module's description (`spec/box-contract.md`, section 4); a built-in box type does not declare one yet (#12 step 40) |
| **port kind** | What an inlet or an outlet carries, which a cable joins only to the same kind: an audio signal so far; sub-sample discontinuities (#12 step 19) and spectral frames (#12 step 42) are reserved for later versions of the box contract | none | `host::PortKind`, its codes in a module's description (`spec/box-contract.md`, section 4) |
| **cable** | A connection from an outlet to an inlet; cables into one inlet are summed in a fixed order, by the reduction order | an entry of `connections` | `Connection` |
| **plan** | The patch compiled for execution: boxes in a deterministic order, buffers allocated once | — | `Plan` (`audio-core`), whose instance type `I`, a type implementing the trait `Dispatch` (`audio-core`), says how it holds and calls its box instances: `BuiltIn` (`audio-boxes`) calls every built-in box type directly and any other through its virtual table, `Box<dyn BoxInstance>` every box type through its virtual table; always named, the engine's plan being `EnginePlan` and its renderer `EngineRenderer` (`audio-boxes`); `Renderer` (`audio-core`) owns a plan to render its frames offline |
| **engine block** | The number of frames the engine processes at once, whatever the host buffer: a constant of the build, one of the sizes the build offers (64 frames by default), a performance setting only, never changing a render (`spec/engine-design.md`, decision 2); a block is that many frames, and each box processes one block per call | — | `Block<S, N>`, `BLOCK_SIZE`, `ENGINE_BLOCKS`, `MAX_ENGINE_BLOCK`, `NAMED_ENGINE_BLOCK` (`audio-core`), named by the build variable `POYETIK_ENGINE_BLOCK`; `ENGINE_BLOCK` (`audio-host`); `Plan::process`, `Object::process`; `engine_block_size` (the module) |
| **host** | What runs the engine and chooses its settings: the browser's AudioWorklet, a native audio backend, a desktop shell, a plugin wrapper, an offline renderer; it reads and writes the floats of samples, which boxes never touch | — | the `host` module of `audio-core` (`host::Delivered`, how a render is given to its host; `host::ParamBounds`, a parameter's bounds and default; the box contract's ABI, through which it is to meet a box type compiled to its own module: `host::Header`, `host::Description`, `host::Runs`) |
| **run of buffers** | What the engine hands a box compiled to its own module for its inlets, or for its outlets: one buffer per audio port, in port order, each one span of samples; a buffer's **stride** is its span's bytes rounded up to a multiple of 64, the bytes past the span its **padding** (`spec/box-contract.md`, section 2) | — | `BufferRun`, `BUFFER_ALIGNMENT`, `Crossing` (`audio_core::host`) |
| **header** | Where a box type compiled to its own module says, in its memory, its contract version and its description, read before any of its code runs (`spec/box-contract.md`, section 5) | — | `Header` (`audio_core::host`); the export `poyetik_box` |
| **host buffer** | The span of frames a host asks the engine for at once (an audio callback, a call of an offline render); any length, and the result never depends on how a render is split into host buffers | — | `Renderer::render`, `Renderer::render_into`, `WasmEngine.render`; the sizes tested are `host_buffer_sizes` of the test matrix |
| **render quantum** | The frames a browser's audio thread processes at once (Web Audio): the host buffer of the engine in a browser, and what a tap delivers | — | `RENDER_QUANTUM` (its default, 128 frames), `BrowserSettings.renderQuantum` (`audio-wasm`, `./web`); `tap` and its `onBlock` callback, `parseTapMessage` (`audio-wasm`; names kept until #32 step 15) |
| **frame**, **sample** | A frame is one instant of every channel; a sample is one channel's value at one frame (a binary64 or binary32 float, by the precision) | — | `Binary64` or `Binary32` (`Sample`, `audio-core`), given to hosts as `f64` or `f32`; planar (one buffer per channel, mono `Block`s) inside the engine and in `WasmEngine.render`; interleaved by channel in `Renderer::render`, `Renderer::render_into` and the render hash |
| **precision** | What a render computes its signals in: IEEE 754 binary64 by default, binary32 as a host setting; parameter values and what boxes derive from them are binary64 in both (`spec/engine-design.md`, decision 10) | — | `Precision`, `Sample` (`audio-core`); `precisions` of the test matrix |
| **render format** | The precision of a render and the format its samples are given in: `binary64`, `binary64-as-binary32` (computed in binary64, each sample rounded to binary32 for a host that takes binary32) or `binary32`; a case has one reference hash per render format | — | `RenderFormat`, `host::Delivered` (`audio-core`), `Samples` (`audio-hash`) |
| **math layer** | The engine-owned sample types with their operators and the math functions (the pinned `libm`), the only path of box arithmetic, a product then a sum included (`mul_then_add`) | — | `Sample`, `Binary64`, `Binary32` (`audio-core`; their floats reached only through its `host` module); `cargo xtask check` refuses `libm` in any other crate but the measurements' (tests apart), and raw floats in box code |
| **reduction order** | The one order every sum of more than two terms follows (`spec/engine-design.md`, decision 28): term `k` into lane `k mod 16`, each lane summed in increasing `k`, then a fixed pairwise tree of the 16 lanes; never the vector width of a machine, so vectorizing never changes a bit | — | `ordered_sum` (`audio-core`, its math layer); `cargo xtask check` refuses the iterator reductions in box code and in the engine core outside it (a loop that sums is reviewed) |
| **algorithm version** | The version of a box type's algorithm, counted from 1: any change that can change a bit of its output takes a new one (`spec/engine-design.md`, decision 29); the conformance references record the versions they were blessed with, the check refuses others, and bless refuses bits changed without a new one | in format version 2 (roadmap #3 step 7) | `AlgorithmVersion`, `ObjectSpec::algorithm_version` (`audio-core`); `conformance/algorithms.json`, written by `cargo xtask bless` |
| **output stage** | What the engine applies to every block after the plan, before delivery and before any hash (`spec/engine-design.md`, decision 12): a non-finite sample (NaN or infinite) replaced by zero and reported, how many and the first; raw (nothing more), protected (the true-peak limiter too, from the first block, never switched to raw) or switchable (the limiter's latency, raw first, then protected or raw by a crossfade), a host setting; limited: with the limiter, protected or switchable; the limiter's rest: a frame by which a count of frames since its last need (a frame needing a reduction) or its last change of pace certifies its whole control state that of a limiter at rest at any lookahead, where a lookahead set live, pending until then, takes effect (applied, in force, taken: one concept; the share of its reduction a crossfade applies is another) | — | `OutputStage`, `Replaced`, `TruePeakLimiter`, `LimiterMode`, `LimiterSettings`, `Detector`, `pending_lookahead` (`audio-core`); `Output`, `LimiterStage`, `OutputMode` (`audio-host`); `engine_replaced`, `engine_output`, `engine_limiter`, `engine_protect`, `engine_latency`, `engine_lookahead_pending` (the module); `Output`, `RawOutput`, `LimitedOutput` (`ProtectedOutput`, `SwitchableOutput`), `LimiterStage`, `MIN_LOOKAHEAD`, `MAX_LOOKAHEAD`, the engine node of each mode (`RawEngineNode`, `ProtectedEngineNode`, `SwitchableEngineNode`) and its handlers (`RawHandlers`, `LimitedHandlers`), `setLimiter`, `setProtected`, `lookaheadPending`, `onReplaced`, `onRefused`, `onLookaheadApplied` (`@poyetik/audio-wasm`) |
| **execution mode** | How a plan runs, never part of its result (`spec/engine-design.md`, decision 20): live (a deadline every host buffer), offline (no deadline) or build (the export, frozen, giving an offline render's bits); a box type is **live-capable** (runs in every mode, under the real-time rules) or **offline-only** (may allocate while processing; refused by a live plan) | — | `ExecutionMode`, `BoxMode`, `Create::BOX_MODE`, `ObjectSpec::mode`, `CoreError::OfflineOnly` (`audio-core`) |
| **host settings** | What a host asks of the engine (the sample rate, the engine block, the output and input channels) and the settings it applies, with one reason for each it applies otherwise (`spec/engine-design.md`, decision 1) | — | `HostSettings`, `OutputChannels`, `InputChannels`, `AppliedSettings`, `Unhonored` (`audio-core`); `BrowserSettings`, `LoadedPatch.settings` (`@poyetik/audio-wasm`) |
| **render rules version** | The version of the engine's own rules for the bits of a render no box type owns (the plan's sums, event timing, flush points, the output stage, delivery): any change of them that can change a bit takes a new one (decision 29) | in format version 2 (roadmap #3 step 7) | `RENDER_RULES_VERSION` (`audio-core`); recorded in `conformance/algorithms.json` |
| **fingerprint** | The hash of a box type's outputs at one algorithm version over a fixed battery of inputs, recorded beside the conformance references: it shows a bit change wherever the battery reaches, beyond the conformance cases (decision 29) | — | `fingerprint`, `FINGERPRINT_BATTERY` (`audio-battery`); `conformance/algorithms.json` |
| **arithmetic mode** | The set of arithmetic options the math layer is built with (fused multiply-add, reassociable operations, platform math functions), one flag each, unknown flags refused; all off is the strict mode, the only one built, and the render hash records it | — | `ArithmeticMode`, `ArithmeticOption`, `MODE` (`audio-core`) |
| **subnormal** | A nonzero float below the smallest normal value (2^-126 in binary32, 2^-1022 in binary64), which some CPUs compute slowly and some hosts flush to zero in hardware; the engine flushes it to a zero of its sign itself, at defined points (`spec/engine-design.md`, decision 11), and the output stage's limiter keeps its control path above the subnormal numbers altogether, every value it keeps through `math::kept` (a release stage, a share, an applied reduction) zero or at least a threshold of 2^-100, its Hann sums, derived from those, proven zero or normal, so that every target computes the same bits; the visual library never writes one: every value of an image is finite, never subnormal and never -0, a box writing 0 instead (`spec/visual-design.md`, section 3, held by the visual box laws' finite values) | a subnormal parameter is zero | `Plan::build`, `ParamValues::of` and `ParamValues::defaults` (`audio-core`) flush every parameter below 2^-126 (a binary32 value as a plan reads it, a binary64 one as its own; decision 11); `Sample::flush` (`audio-core`) flushes box outputs and recursive states; `host::Delivered` flushes every delivered sample, skipped where `Plan::channel_is_sum` proves it changes no bit |
| **audio library** | The engine as a library usable on its own: its crates need nothing else of the project but the time crate, their tests also its test crates (`spec/engine-design.md`, decision 32); a library of another domain beside it, the visual library (`spec/visual-design.md`), is a **sibling library** | — | the crates of xtask's `RUST_CRATES` holding `CrateRole::Library`, kept apart by the library gate |
| **time map** | Musical time as data: a sequence of segments (constant tempo, tempo curves, recorded beat positions, jumps) giving the position of every frame, built by the host or the coordinating layer (`spec/engine-design.md`, decision 17) | planned (#3 step 8) | planned (the time crate) |
| **time crate** | The tiny standalone `no_std` crate holding the time map and its exact evaluation, shared by the audio library, the visual library and the coordinating layer (decisions 17 and 32); its results carry an **evaluation version**, recorded by each time map (decision 29) | each time map's evaluation version (planned, #3 step 8) | planned (#37) |
| **transport** | A named musical-time clock that a subpatch follows; its controls (play, stop, loop, locate, derived transports, the master clock) belong to the coordinating layer, and on the audio thread the **transport box** (or a transport service of the plan) evaluates its time map (decision 17) | which transport each subpatch follows (planned, #3 step 8) | planned (#12 step 35) |
| **coordinating layer** | The layer above the libraries, outside the engine: what runs asynchronously (interface, files, network, an assistant), heavy logic ahead of time, time alignment between the libraries, the choice of clock, transport controls, scenes and cues spanning several libraries; never on the audio thread (decisions 1, 17, 19, 32 and 33); its logic lives in the `no_std` crate `coordinator`, first the image a visual sequence shows at each frame of the audio clock, and the page module that links it is built by `bindings/web-page` (decision 33) | — | `coordinator::image_at`, exported as `page_image_at` (`web-page`), `PageModule.imageAt` |
| **sample rate** | Frames per second, 8 000 to 384 000 Hz | — | `SampleRate` |
| **render** | The output of a patch over a duration at a sample rate, offline | — | `Renderer` (`audio-core`), of a known length (`Lasting`, `Renderer::lasting`, whose rest `Renderer::render_rest` renders) or without one (`Endless`); `audio-cli`, `renderOffline` (browser) |
| **render hash** | The SHA-256 of a render in canonical form: render format, arithmetic mode, rate, channels and every sample's bits; equal hashes mean identical renders (`spec/render-hash.md`) | — | `render_hash` (`audio-hash`), `renderHash` (`@poyetik/audio-wasm/hash`, and the oracle's own) |

## Visuals

The visual library, standalone (it depends on no other part); its design decisions are in `spec/visual-design.md`.

| Word | Meaning | Code |
|---|---|---|
| **visual library** | The library of images, the audio library's sibling at the same rank: its crates need nothing else of the project but the time crate, their tests also its test crates (`spec/visual-design.md`, section 1) | the crates of xtask's `RUST_CRATES` holding `CrateRole::VisualLibrary`, kept apart by the library gate |
| **image** | One picture of a visual render, at one instant; never called a frame, which is audio's | `Image` (`visual-core`) |
| **image rate** | Images per second, an exact reduced fraction (`24000/1001`), 1 to 1000 | `ImageRate` |
| **image index** | The position of an image in a sequence, from 0; image `n` is at `n / rate` seconds exactly | `ImageIndex` |
| **visual box** | One processing unit of a visual patch: renders an image as a pure function of its index, its parameters and the size of its output | `VisualBox` (`visual-core`), the boxes in `visual-boxes` |
| **subpixel unit** | 1/4096 of a pixel side, the unit of every coordinate of an image | `SUBPIXELS`, `SubpixelPoint` |
| **coverage** | The area of a pixel a shape covers, an integer from 0 to 2²⁴, converted exactly to light intensity | `coverage_to_intensity` |
| **image hash** | The SHA-256 of a sequence of images in canonical form: rate, size, encoding, every value's bits and the number of images; equal hashes mean identical sequences (`spec/image-hash.md`) | `ImageHasher`, `ImageHash` (`visual-hash`) |
| **visual box laws** | The properties every visual box must respect (determinism, random access, size change, overwrite, finite values, no heap operation, pure trace), at every value of the visual test matrix | `check_laws` (`visual-testkit`) |
| **visual test matrix** | The image rates, sizes and indices every visual law is checked at, never retyped | `conformance/visual/test-matrix.json`, `visual_testkit::matrix` |
| **trace** | What produced a point of a box's output (a shape, the background, or not declared): how a gesture on an output finds what it touched | `Trace`, `VisualBox::trace` |
| **CPU** | The machine's central processor, as opposed to its GPU: the CPU reference renders on it, and the playground draws the square on it where the browser has no GPU; never "the processor" in that sense, the word of the audio worklet's processors (the engine processor, the tap processor) | the CPU reference (`visual-core`); the playground's `DrawnBy` `"cpu"` (`Square.tsx`) |
| **placement** | Where the square is in one image of a size: the half-open rectangle it covers, its four edges in subpixel units, exact, as the CPU reference renders and traces it and as a GPU draws it | `Placement`, `Square::placement` (`visual-boxes`); `visual_placement`, `VisualDriver.placement` |
| **display encoding** | An image as a screen, a canvas or an 8-bit file takes it: 8-bit sRGB with straight alpha, four bytes a pixel, exact on every target | `DisplayImage`, `pixel8` (`visual-core`) |
| **display corpus** | The values reaching every path of the display encoding, each pixel with the bytes the native encoding gives it, which every target must give too | `conformance/visual/display.json` |
| **product module** | A WebAssembly module of a product, linking a library with what spans it (the coordinating layer), one per thread | `web-page` (`page.wasm`, `PageModule`), the one product module so far |
| **page module** | The product module a browser page loads: the visual library and the coordinating layer in one module, never two side by side | `web-page` (`page.wasm`), `PageModule` |

## Proof

| Word | Meaning | Where |
|---|---|---|
| **conformance case** | A patch, a rate and a duration whose render hash is recorded and must be reproduced on every target | `conformance/cases/` |
| **reference hash** | The recorded hash of a case, or of the live vector, in one render format; it changes only through `cargo xtask bless`, and the commit says why | `conformance/references.json`, `conformance/live-references.json` |
| **live vector** | A patch of the corpus rendered through a protected output stage whose limiter's settings change between engine blocks, scripted, whose reference hashes must be reproduced natively and in WebAssembly (`spec/engine-design.md`, decision 12); a changed hash is blessed only with `cargo xtask bless --live-changed` | `conformance/live-limiter.json`, `conformance/live-references.json` |
| **oracle** | The independent checker: rereads the native renders and checks them against the mathematical definition of their signal, sharing no code with the engine | `tooling/oracle/` |
| **measurement** | An objective level of a signal (spectrum, THD+N, THD, SNR, SFDR, aliasing level), defined in `spec/measurements.md` and computed twice, independently | `audio_testkit::measure`, the oracle's `measure.ts` |
| **threshold** | The worst level a box or an engine component may measure, derived from first principles (its error bound per sample, then the bounds of `spec/measurements.md`), never declared | `sine_bounds` (`audio-testkit`), `sineBounds` (oracle) |
| **test matrix** | The shared values every dimension is tested across (rates, host buffer sizes, …), never retyped | `conformance/test-matrix.json` |
| **seam** | What a piece of code is given in place of what the machine or a device does for it, a function, an argument or a field a test replaces (allocating an image, counting heap operations, encoding for display, waiting on a GPU, the GPU a benchmark measures): the machine's own in use, a test's in its tests, so that a refusal the machine gives only when it runs out, such as no memory left, or a GPU refusing a pass, is tested on every machine | `Seams` (`visual-cli`, `visual-testkit`); the `count` argument of `operations_counted_by` and `bytes_counted_by` (`alloc-counter`); the `make`, `image` and `display` arguments of `visual-host` and `visual-cli`; `GpuSquare`'s `wait` and the benchmark's `open` (`visual-gpu`); `TimedGpu`, the GPU `measure` takes (`visual-gpu`) |
| **box laws** | The properties every registered box must respect, each box run in isolation, listed in the crate documentation of `audio-testkit` | `audio-testkit` (`check_laws`) |
| **plan laws** | The properties every plan must respect, checked over random patches, among them that a render never depends on how it is split into host buffers; listed at the top of their test file | `crates/audio-testkit/tests/plan_laws.rs` |
| **bit-defining** | Said of a dependency whose code computes output samples, images or hashes, or the values they are computed from: every normal or build dependency of the audio library or of the visual library is one, as are the case readers of the command-line tools; each direct one is pinned to one exact version, and an update follows decision 29 of `spec/engine-design.md` | `dependencies.txt` (a reason starting `bit-defining: `), xtask's pin gate |
| **spent**, **spent record** | An algorithm version or render rules version is spent once it reaches `main`: its bits never change again (`spec/engine-design.md`, decision 29). The spent record is `conformance/algorithms.json` as `main` holds it, at the merge base of `MAIN_BASES`, which bless and the conformance check compare with | `--spent` (`audio-cli`); `MAIN_BASES`, `SPENT_RECORD` (`crates/xtask/`) |
| **mutation proof record** | What a passing default check on a clean tree records of its Rust mutation testing (the commit, its tree, the merge base, the host and the tools), so that a later default check of the same base skips the crates whose inputs are unchanged since; it never changes what the check proves | `ProofRecord` (`crates/xtask/`), in git's common directory |
| **check** | `cargo xtask check`: every quality check, mutation testing only the changes (Rust since the merge base, xtask's `MUTATION_BASES`, but the crates an earlier default check of that base proved and left unchanged, its mutation proof record; TypeScript since the last local Stryker run); the pre-push hook runs it after its own refusals | `crates/xtask/` |
| **full check** | `cargo xtask check --full`: every quality check and every mutant, as CI runs it | `crates/xtask/` |
| **check step** | One named part of the check (formatting, a lint, a test suite, a gate), run in a fixed order; `cargo xtask list` lists them. Not a roadmap **step** | `Step` (`crates/xtask/`) |
| **part of the full check** | One slice of the full check that one CI job runs (`cargo xtask check --full --part <part>`; `cargo xtask list --full --parts` lists them); together they run every check step once, only preparation repeated. Not a part of the repository, nor a part of the native check | `Part` (`crates/xtask/`) |
| **part of the native check** | One slice of `cargo xtask check --native` (audio, visual, GPU), run only when the changes since `main` reach it. Not a **part of the full check**, nor a part of the repository | `NativePart` (`crates/xtask/`) |
| **slow group** | The tests of a workspace listed in its nextest configuration and run last in every mutant run, so that the fast tests, which catch most mutants, run first: chosen at `SLOW_TEST_MILLIS` (0.5 s) in the baseline of its mutation runs, then kept within a band, a test outside it suggested in from `SLOW_TEST_SUGGESTED_MILLIS` (1 s) and a test of it suggested out below `FAST_TEST_MILLIS` (0.25 s), so that the load's noise moves no test in and out at each run | `.config/nextest.toml` of each workspace; `test_order::slow_group`, `SLOW_TEST_MILLIS`, `SLOW_TEST_SUGGESTED_MILLIS`, `FAST_TEST_MILLIS` (`crates/xtask/`) |
| **mutation shard** | One of the slices cargo-mutants splits the Rust mutants into (`--shard`), each run by a part of the full check of its own | `Shard` (`crates/xtask/`) |
